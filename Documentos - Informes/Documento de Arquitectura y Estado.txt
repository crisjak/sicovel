Documento de Arquitectura y Estado Técnico - SICOVE
Fecha Base: 11 de Abril, 2026 Fase de Desarrollo: Frontend Core & UI Engineering Estabilizado

Este documento detalla exhaustivamente toda la ingeniería de frontend, arquitecturas elegidas y parches a nivel renderizado implementados en el proyecto SICOVE hasta la fecha.

1. Stack Tecnológico Estructural
La aplicación está montada bajo un ecosistema moderno orientado al alto rendimiento en el cliente sin bloquear la precarga del servidor.

Framework Principal: Next.js 15 (App Router).
Renderizado: React 19 (con uso intensivo de Componentes de Servidor "use server" por defecto, y Componentes de Cliente "use client" estrictamente encapsulados en piezas interactivas).
Lenguaje: TypeScript estricto. Requerimiento absoluto para interfaces gráficas e intercambio de Props.
Gestor de Estilos: Tailwind CSS v4.
Motor de Interacciones & 3D: Framer Motion (manejo de interpolación física, resortes - springs -, y gestos táctiles de arrastre fluido).
Gestión de Tema: next-themes actuando como Provider inyectando la manipulación segura del DOM (clase .dark en el <html>) evitando el FOUC (Flash of Unstyled Content).
2. Arquitectura de Layout y Estilos Globales
Se consolidó una reingeniería del diseño para garantizar un lienzo unificado, eliminando la rotura visual por agrupaciones de páginas (secciones modulares).

Fondo Global sin Fricción: El app/layout.tsx ahora aloja los gradientes en el body. Esto significa que la aplicación corre sobre un único <div className="fixed inset-0 ...">, optimizando la GPU y permitiendo transiciones de rutas fluidas sin recálculo de texturas de fondo.
Tipografía Dinámica: Estilos encapsulados con variables CSS y tokens de Tailwind en globals.css.
Títulos Sistematizados: Implementamos un estándar de diseño para SectionTitle.tsx, que fragmenta la gramática dividiendo siempre los títulos en dos colores dinámicos (Ej: [Azul Noche/Celeste en light mode] vs [Celeste brillante/Celeste mixto en dark mode]).
3. Despliegue de Componentes Core (UI Layout)
A. Barra de Navegación (Navbar.tsx)
Reconstruida bajo filosofías de diseño "Tech Startup Hiper-Minimalista":

Transparencia de Vidrio (Glassmorphism): El elemento raíz usa backdrop-blur-md junto a un fondo semitransparente que garantiza contraste asimétrico a medida que el usuario hace scroll, sin mostrar contornos rudos (bg-white/80 dark:bg-slate-950/80).
Navegación de Escritorio (gap-5): Implementada con enlaces puros (<Link>). El feedback hover se ejecuta vía CSS puro interceptando colisiones (hover:-translate-y-1 para ascenso gravitatorio y un [text-shadow:0_0_12px_rgba(6,182,212,0.6)] para emisión sutil de luz/glow). Se removieron contenedores div redundantes.
Navegación Móvil (AnimatePresence): Controlado por un árbol <AnimatePresence> de Framer Motion manipulando height: 'auto' y opacity. El componente no solo desaparece de la vista, sino que es limpiado y montado dinámicamente del DOM React, previendo fugas de memoria (memory leaks).
B. Gestor de Nodos Temáticos (ThemeToggle.tsx)
Patrón de Inyección (Polimorfismo CSS): Transformado de una posición fixed rígida a un componente receptivo de props (interface { className?: string }).
Microinteracciones Simultáneas: Combina animaciones de rotos y escalas cruzadas. Mientras el estado "Mes/Luna" recibe scale-0 y rotate-90, el estado "Sol" recibe scale-100 e inversos.
Ubicación Condicional: En PC el toggle existe en el Layout raíz flotando a la derecha hidden md:block. En dispositivos pequeños, bloquea su carga y es instanciado como una fila directa dentro del sub-menú de Navbar.tsx para optimizar pulgares.
4. Ingeniería 3D y Superación de Bugs Motores de iOS
Componente ServiceCarousel.tsx
Este componente ha sido el más complejo a nivel ingeniería DOM y GPU WebKit. Presentaba un comportamiento documentado de pérdida de resolución, específicamente en despliegues iOS WebKit y Chromium Mobile (Raster Layer Lock).

La Falla (Rasterización WebKit)
Framer motion calculaba matemáticamente filter: blur(3px) durante la transpolación de una carta que se arrastraba. Los navegadores móviles, para no congelar el celular, apagaban el motor vectorial y tomaban una foto de mapa de bits (bitmap de baja resolución). Cuando la tarjeta llegaba al centro (blur(0px)), la GPU olvidaba restaurar el vector dejando la imagen "sucia". Adicionalmente, el <Image> estiraba mal su configuración intrínseca.

Solución Definitiva (El Parche Multipropósito)
DPI Forzado (Retina Fix): La directiva <Image> de Next.js fue reconstruida desde un sizes="100vw" genérico a una reserva de espectro físico sizes="(max-width: 768px) 800px, 400px". Combinado con un quality={100} estricto, esto exige al servidor entregar siempre imágenes UHD a los celulares que reporten densidades altas (ej x3 en iPhones The iOS).
Extirpación del Bug Interpolatorio: Se erradicó el diccionario filter de los variants en Framer Motion.
Transistores DOM Físicos: El despapelado (blur) falso de las tarjetas fondo se construyó envolviendo a los hijos en su propio layer <div className={isActive ? 'blur-0' : 'blur-[4px]'}>. Cuando el carrusel hace focus al centro, React expulsa sintácticamente el tag SVG del blur, obligando coercitivamente al motor del celular a tirar la foto temporal de la RAM de video y rendir la tarjeta 100% vector y nitidez real.
Cortina Tenebrosa: Se añadió una envoltura superior transparente (capa superior Z) con opacity-100 bg-[#0a0f1c]/60 para simular profundidad atmosférica cuando están detrás, destruyéndose (opacity-0) al venir a frente. Todo esto sin colisionar el 3D render.
Acelerador Gráfico: Las imágenes traen inyectado un style={{ WebkitTransform: 'translateZ(0)' }}, que enciende obligatoriamente la aceleración gráfica paralela del dispositivo.
5. Diseño Data-Driven (Headless Flow)
Toda la data provista al Navbar y Carruseles (@/types/content) no está hardcodeada dentro de las etiquetas UI. Todos extraen información de interfaces en JSONs o Props enviadas desde estructuras maestras, asegurando que cuando el Panel Admin entre en fase final, la conexión del Backend sea limpiar, pegar y despachar.
